# 深度分析使用说明

当指标或记录有值得继续核查的问题时使用 deep-analysis；普通 hover、样式调整和单纯表格展示沿用现有交互。计算与证据按 [data-analysis](data-analysis.md)，通用规则见[深度分析指南](../../../references/deep-analysis/interaction.md)。

## 入口与接入

围绕“入口 → 比较或检验 → 明细核对 → 清除或返回 → 关闭”组织动线；每次深入增加证据、缩小核查范围或揭示权衡，不仅放大数字、换分组或重复排行。复杂内容按动作展开，默认复用模板 Modal；用户指定其他容器时沿用宿主。

复用 [analysis.js](../assets/analysis.js) 的 `bindMetricAnalysis()`，传入主页现有 `vbi`、`dataQuery`、`Builder`、`VChart`、`motion`，以及 `entries`、`getContext`、`ready`、主页重试函数 `retryScope`；组件结构与生命周期见 [UI 组件](components.md#布局与深入分析)。

| 配置                                                          | 适配要点                                                                                                                                                             |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `entries`                                                     | 用 `heading`、`value` 选择器绑定指标名称与数字，按需设置 `card`；组件处理点击、键盘与控件事件隔离。                                                                  |
| `getContext(index)`                                           | 打开时构造当前上下文；`connectorId`、`rowLimit`、`scope` 对应数据集、完整结果上限与范围说明。                                                                        |
| `metric`                                                      | 配置 `title`、`conditions`、`measures`、`value(row, prior)`、`format(value)`、`definition`；可比基期用 `previous`，分组或时间切片口径不同则适配查询与选择条件。      |
| `dimensions` / `detailDimensions`                             | 维度元组为 `[field, label, ordered?, type?]`，`ordered: true` 绘制有序趋势，数值型筛选值用 `type: 'number'`；`grain` 说明明细粒度，`defaultDimension` 指定初始维度。 |
| `entryConditions`                                             | 以稳定业务键固定单元格或图元的入口范围，后续查询持续叠加；不用图形或行列下标代替业务身份。                                                                           |
| `analysis`                                                    | 可选 `DashboardAnalysis` 配置问题、指标、记录量与交叉维度；`relation` 配置有业务含义的横纵指标及配对字段。                                                           |
| `analysisConditions` / `analysisScope` / `analysisDefinition` | 关系图与交叉分析使用的已确认条件、范围标签和口径说明；指标固有时点与探索区间不同时显式配置，图形、读数、分组与关联明细共用该范围。                                   |

条件条目使用 `{ field, operator?, value }`，省略运算符为等值；度量条目使用 `[field, label, aggregate]`。字段变化时同步指标、筛选、分析入口与明细映射。

返回的控制器通过 `bindTable(table, tableAnalysisContext)` 接入主页分析表，按列字段与记录业务键映射指标和入口条件；表头及总计行不作为来源记录。宿主退出时先 `dispose()` 解绑分析，再释放主页表格。

## 范围与证据

- 打开继承已确认筛选与指标固有条件，不携带 hover 或上一次入口的选择；深度查询按需加载，主页查询独立完成。
- 图表和菜单共用局部选择，读数、发现与明细来自同轮结果。切换维度重置当前分组，保留入口条件；清除或返回恢复入口范围，局部探索不改写主页。
- 关系图两轴需有业务含义、有效配对及变化，不默认以记录数解释指标；单值或配对不足时改用比较或明细。交叉定位同时叠加真实字段，解释边界按数据分析规则处理。
- 明细用 VTable，图形截断后仍能检索和选择完整分组；只有汇总时说明无法穿透原始实体。列条件只影响关联明细及其汇总，切分组保留兼容条件，接入见[表格适配器](../../../references/visual-query/references/table-theme.md#列搜索过滤与排序)。

## 更新与返回

- Modal 上方复用可操作的全局筛选器。主页提交最新结果后调用 `updateScope()`，重新构造当前入口上下文，保留分析维度与稳定业务键、清除局部分组；失败调用 `updateScope(error)`，在弹窗内反馈并通过 `retryScope` 重试主页查询。关闭后控件归位，保留已确认的全局条件。
- 查询期间保留已确认内容并反馈更新状态；快速切换、关闭与重开使旧请求失效，提交前检查版本，失败可重试，空结果可恢复。
- 复用主页连接，关闭分析不释放仍被主页使用的连接；图表 `updateSpec`、表格原位更新，保留必要状态，不重播入场，减少动态效果时直接呈现终态。
- 复用组件的关闭、键盘与焦点行为；关闭取消在途查询、清理本次视图，保留主页筛选、实例及滚动位置，焦点回入口。弹窗开关、请求和实例归 UI，可恢复定义按[数据分析](data-analysis.md#计算与查询)处理。

按[专项验收](acceptance.md#深度分析专项验收10-项)实际点击指标名称及数据格，走通完整动线，核对连续切换、空结果与失败重试；桌面、390px、键盘和减少动态效果均可操作，源码存在或历史结果不计作本次运行通过。
