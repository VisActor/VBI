# 视觉设计最佳实践

适用于轻量 Dashboard、指标卡和趋势图。参考[24 份模板](templates.md)的主题、背景与玻璃透光实现。本文集中维护设计差异、色板、颜色变量和背景实现；布局与入场动效见[设计与布局最佳实践](layout.md)，数字层级与迷你图见[指标卡最佳实践](metric-card.md)。当前模板的布局与主题固定在各文件中，主题切换控件仅在用户需要时提供。

## 相近风格中的差异设计

先实际查看最贴近任务的模板 HTML 与截图，再比较另一份不同结构或主题的参考。保留轻量、克制、数据优先的共同风格，同时独立决定下列设计；不把一套主辅网格、蓝紫渐变和圆角阴影当成所有任务的默认答案。已有品牌或宿主规范优先，在其允许范围内变化。

| 维度         | 可以变化的设计                                                                                       | 保持的质量                                                           |
| ------------ | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 布局骨架     | 左主右辅、右主左辅、全宽主区后接指标行、指标先行、分段叙事；按问题调整阅读顺序与主辅面积。           | 一个清晰主问题，相关信息成组，密度适中；不为变化编造时间轴。         |
| 背景与阅读面 | 近白暖灰纸面、冷灰细边线、低饱和外围渐变；改变冷暖、光源位置与渐变分布，卡片可用柔和阴影或克制边线。 | 内容底面稳定、文字与图形清楚；背景不抢主指标，不靠增加特效制造差异。 |
| 主题色       | 按语境选择蓝紫、陶土、珊瑚、灰玫瑰、琥珀、钢灰等；布局与颜色自由组合，不固定行业皮肤。               | 页面与图表统一，主强调色明确；正负、风险和类别仍按数据语义表达。     |
| 字体与细节   | 在整页统一的前提下选择界面式或报告式字体、圆角、边框和标题节奏。                                     | 同层级数字共用字号、字重和数位样式，不用忽大忽小制造变化。           |

例如零售金额趋势页用全宽主图与珊瑚色，品类结构页可用右主左辅与石油蓝；能源长期观察采用琥珀纸面，部门比较采用湖蓝细边线。这些选择因分析重点而变，不是行业专属规则。暖色页面不必继续保留蓝紫背景；背景应与所选主题协调，也可保持纯净中性底色。

生成一组看板时并排查看缩略图：布局、背景、主题应形成可辨识的组合差异，而不是同一页换色。单页新设计也要说明相对参考保留了什么、为什么改变；不得以多样性为由降低图表、交互、字号层级或信息密度的质量。字号统一使用[数值字号规范](metric-card.md#数值字号规范)，差异主要由结构、色彩与背景承担。

## 参考色板

提供八种柔和参考色。色号作为强调色的输入，浅背景、图标底色和辅助色由它派生；无需为每个预设分别维护整套样式。这些颜色是参考起点，不是可用颜色的完整清单；可根据当前场景、品牌、已有视觉风格和用户要求自行设计新的配色，遵循下方颜色层级与可读性原则。

**按需选择主色系，降低绿色系的选择优先级；没有明确需要时，不选择绿色作为主强调色或大面积背景的主色。** 先遵循用户指定配色与已有品牌、界面风格，再结合业务场景选择适合的色系。上下文未指定时，优先考虑合适的蓝、紫、粉、暖橙等非绿色系，也可设计新的配色；不要把任何一种替代色固定为所有 Dashboard 的默认色。

薄荷绿、森雾青、竹月青等偏绿或青绿色都适用这一限制。仅当用户明确要求、既有品牌规范或业务场景确需绿色时才选择；“清爽”“自然”“通透”“增长”等泛化描述不足以成为整页使用绿色的理由。局部数据的绿色语义不等于页面需要绿色主色系。参考示例时，不把色板首项、当前选中色或截图主色当作默认答案。

| 配色   | 色号      | 适合的视觉气质                       |
| ------ | --------- | ------------------------------------ |
| 海盐蓝 | `#AFCBDA` | 清透、宁静，适合信息密度较低的看板。 |
| 晴空蓝 | `#A8C7E8` | 清朗、开阔，适合轻快的趋势展示。     |
| 薰衣紫 | `#B9AFD8` | 柔软、静谧，适合轻盈通透的界面。     |
| 雾玫粉 | `#D8B4B6` | 温柔、安静，适合柔和的经营概览。     |
| 杏桃橙 | `#F0C4A8` | 温暖、明亮，适合带日光感的界面。     |
| 薄荷绿 | `#16C99E` | 清爽、轻盈，强调趋势与选中状态。     |
| 森雾青 | `#7FA69A` | 自然、沉稳，带森林与雾气的感觉。     |
| 竹月青 | `#89A8A0` | 清雅、平和，适合克制的中性界面。     |

一个 Dashboard 每次选择一个强调色，统一用于主要系列、选中控件和重点图标；通过明暗和透明度建立层级。两种背景色负责营造氛围，不为每张卡片另分配一种系列色。辅助图标和环图的浅色部分来自同一套派生规则。

颜色不能单独承担信息表达。下降、亏损和选中状态同时通过箭头、数值、位置或文字表达；经营概览模板的下降文本消费 `--down`，亏损柱使用语义红；主题切换时保留其业务含义。

## 配色反例：装饰压过数据

经营看板应先让人看到指标、趋势和筛选状态，再感受到背景氛围。大面积亮青、紫色和粉色渐变，叠加透明卡片、彩色表格底色与发亮白边，容易让背景成为视觉主体。即使大数字仍然清楚，这种配色也会削弱标题、日期、单位和图表的阅读层级。

以下特征适用于识别本类轻量看板中的配色失控，不将某个色相本身判为错误：

| 典型特征                                     | 对阅读的影响                                   | 改进方式                                                                                       |
| -------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 大面积青、紫、粉色块同时具有很强的存在感     | 多处装饰同时吸引注意，缺少安静的中性色区域。   | 以近白或浅灰底色为主，降低背景色的彩度、对比和覆盖强度；两种背景色只营造轻微氛围。             |
| 背景、卡片、嵌套面板和表格连续透明叠色       | 阅读面随底层渐变变化，同一张卡片出现不同色偏。 | 使用稳定、低饱和的阅读面；外层保留玻璃透光，内层只叠轻薄底色，不重复模糊，检查合成后的对比。   |
| 青色图表、粉色卡片、紫色表格各占一组视觉重点 | 装饰色形成多个强调中心，颜色与数据含义脱节。   | 保持一个信息强调色；两种背景色不用于区分卡片或给表格行上色，语义红仅用于下降、亏损等数据含义。 |
| 折线和面积填充与背景颜色接近                 | 图形轮廓与页面色块融合，趋势变得不突出。       | 在稳定的中性阅读面上绘图，保留清晰线条，降低面积填充强度；透明 Canvas 仍需要清晰的底面。       |
| 浅灰标题、日期和单位直接落在变化的渐变上     | 不同位置的对比不一致，次要信息需要费力辨认。   | 文字使用稳定的深浅中性色，检查透明层合成后的实际底色，不能只检查 CSS 中的单个色号。            |
| 每张卡片都叠加强烈白边、光晕或局部高光       | 所有边缘同时被强调，装饰轮廓与内容争夺注意。   | 使用薄的透光边缘、内缘高光与柔和阴影，避免强反光或发光轮廓。                                   |

“模糊”“浅色”“透明”不能替代低饱和与清晰层级：模糊只柔化边界，不会自动降低彩度；明亮的粉紫色仍可能很抢眼；过于透明的卡片会透出底层颜色，也不会自动显得轻盈。若 Prompt 只强调“液态玻璃、渐变、通透”，Agent 容易把这些词落实为多层特效叠加；应同时约束颜色的用途、覆盖区域和内容底面。

## 玻璃阅读面

24 份模板的 `dashboard-material` 样式统一维护玻璃 token，参考地图模板的单层毛玻璃、内缘高光与柔和阴影。主页卡片与明细容器沿用同一组材质 token：`--glass-background`、`--glass-edge`、`--glass-filter` 和 `--glass-shadow`。上方指标卡采用约 46% 白色底层与柔白渐变、14px 模糊和约 22px 圆角；底部明细将白色底层降低到约 24%，叠加更淡的 14%–2% 白色渐变，并减轻边缘与阴影，让背景透得更多，与上方指标卡保持层次差异。保留各模板原有主题与背景，玻璃不另加彩色光晕或循环扫光。

分析弹窗消费同一组材质 token，局部将 `--glass-surface` 提高到约 78%，隔开遮罩下的主页文字。弹窗内图表与明细只使用 `--glass-tile` 和轻量内缘阴影，不重复叠加背景模糊。Canvas 继续使用透明背景，VTable 的表头与浅斑马纹通过统一 token 建立稳定阅读面；菜单使用 `--glass-fallback` 保证选项可读。控件消费统一的半透明底色与悬停 token，选中态从主题强调色派生。

不支持 `backdrop-filter` 或用户偏好减少透明效果时，卡片、明细与弹窗使用 `--glass-fallback` 实色底面。在背景最深处和弹窗覆盖密集内容处复核文字与图表，不通过提高背景彩度补偿玻璃感。弹窗内容的入场时序见[弹窗与内容分批入场](layout.md#弹窗与内容分批入场)。

## 统一颜色变量

CSS 是主题颜色的唯一输入。各模板定义 `--accent`、`--accent-ink`、`--chart-track` 及自己的背景参数，`dashboard-material` 定义玻璃与弹窗动效 token；公共 `dashboard-table-tokens` 派生排印、焦点和表格颜色。不要在业务 JSON、图表和 VTable 中分别维护一套主色。

20 份行业模板的 `page-config` 只维护业务配置，`PAGE.accent` 与 `PAGE.track` 从 CSS 读取；三份专题模板的内联 `PAGE` 也使用同样输入。经营概览模板在绘图函数中读取 CSS。字体通过 `--dashboard-font-family` 输入、`--font-ui` 消费；表格颜色由 [Canvas 适配器](../../visual-query/references/table-theme.md)解析成 RGBA，不能把尚未解析的 `var()` 或 `color-mix()` 直接传给 Canvas 渲染器。

例如专题模板初始化时读取图表颜色：

```javascript
const style = getComputedStyle(document.documentElement)
const accent = style.getPropertyValue('--accent').trim()
const track = style.getPropertyValue('--chart-track').trim()
```

这段读取是初始化快照。若添加运行时主题切换，先更新 CSS token，再重新读取颜色并更新缓存视图；不能假定旧 `PAGE.accent` 会自动变化。VChart 使用 `updateSpec()`，VTable 使用适配后的主题调用 `updateTheme()`，同步表头、正文、悬停、选中与滚动条，保留数据范围、列宽与实例。

背景、玻璃、语义色与表格分别按职责派生，不把所有表面统一涂成强调色。浅色强调色仍须复核细线、重点文字和选中边框，不通过加深整页背景补偿。

## 大面积模糊渐变与柔白斜光

选择玻璃渐变背景时，可用两种协调的低饱和色大面积模糊、自然融合；以下示例的柔白光从左上斜穿至右下，边缘柔化并带轻微散射。两种背景色按所选色系搭配，此例为淡蓝与淡紫，不固定使用薄荷绿背景，避免叠加大面积暖黄等第三种色块。光束保持柔白，不随强调色染色。纸面、近白或细边线方案不必添加渐变与光束；不要让所有主题都继承同一蓝紫底色。

下面是可选的双层背景配方，不是模板中的同名维护入口：`body::before` 绘制底层渐变，`body::after` 绘制白色斜光。示例假定已按所选色系定义 `--background-base`、`--background-start`、`--background-end` 和 `--light-edge`；实际模板也可将渐变与柔光合并在同一伪元素中。

```css
body {
  position: relative;
  min-height: 100svh;
  isolation: isolate;
  margin: 0;
  color: var(--ink);
  background: var(--background-base);
}

body::before,
body::after {
  content: '';
  position: fixed;
  pointer-events: none;
}

body::before {
  z-index: -2;
  inset: -18%;
  background:
    radial-gradient(ellipse at 14% 22%, var(--background-start) 0%, transparent 62%),
    radial-gradient(ellipse at 88% 78%, var(--background-end) 0%, transparent 64%);
  filter: blur(64px);
}

body::after {
  z-index: -1;
  inset: -10%;
  background:
    radial-gradient(ellipse at 24% 0%, #ffffffb3 0%, #ffffff00 48%),
    linear-gradient(
      52deg,
      #ffffff00 32%,
      #ffffff14 38%,
      #ffffff70 43%,
      #ffffffd9 46%,
      #ffffff80 49%,
      var(--light-edge) 54%,
      transparent 61%
    );
  filter: blur(18px);
}
```

`isolation: isolate` 将负层级背景留在页面的独立堆叠上下文中；两层伪元素位于内容下方，`pointer-events: none` 保证点击与悬停命中控件和图表。负 `inset` 为模糊边缘预留空间，滚动时背景保持固定。只模糊背景层，不对卡片或 Content 应用 `filter`，保持文字和图表清晰。渐变位置、带宽与模糊半径可按容器比例调整，最终检查光束确实从左上延伸到右下。

## 图表配色与页面同步

在页面内集中定义绘图表面与文字样式，并对所有图表复用：

- 卡片提供稳定底面，图表画布透明或与底面同色；VSeed 使用 `backgroundColor: 'transparent'`。检查最终 Spec 和渲染结果，手写配置或替换图形后也要保留，避免出现矩形白底。
- 图表字体沿用页面字体；标签不带意外描边、阴影或背景块。柱尾标签使用一致的位置策略，为最长数值留空间；无法统一放置时重排，不依赖默认避让造成忽内忽外。
- 轴与网格只保留阅读所需部分。条形比较保留类别名称和零基线；已有精确值标签时可弱化数值轴与网格，不机械套用趋势图的全隐藏规则。
- 色彩表达类别、风险或主次；主题不能覆盖业务语义。无标签 mini 的适用范围见[指标卡](metric-card.md#文本与迷你图配合)。

在 VBI 的 `buildVSeed()` 返回结果上补充视觉属性，再经 VSeed `Builder` 构建 Spec。保持查询结果、字段 ID、统计周期和实例绑定。下表的 `palette` 是从当前 CSS token 读取的呈现对象示意，不是模板额外提供的 API；按图表类型消费同一组颜色：

| 图形       | VSeed 配置                                                  | 颜色来源                                              |
| ---------- | ----------------------------------------------------------- | ----------------------------------------------------- |
| 系列与折线 | `color.colorScheme`、需要显式覆盖时的 `lineStyle.lineColor` | `palette.accent`                                      |
| 面积填充   | `areaStyle.areaColor` 与 `areaColorOpacity`                 | 强调色与低透明度，渐变可按图形需要开启。              |
| 正值柱体   | `barStyle.barColor` 与 `barColorOpacity`                    | 强调色与适度透明度。                                  |
| 亏损柱体   | 负值 selector 的 `barColor`                                 | 固定语义红，不跟随预设变化。                          |
| 两分类环图 | `color.colorScheme`                                         | `palette.ring` 与 `palette.ringTrack`，保持分类顺序。 |

例如利润柱图，`seed` 为已有查询结果，保留零基线与负值：

```javascript
const valueId = seed.measures[0].id
seed.backgroundColor = 'transparent'
seed.color = { colorScheme: [palette.accent] }
seed.barStyle = [
  { barRadius: 2, barColor: palette.accent, barColorOpacity: 0.68, barGradient: false, barBorderWidth: 0 },
  {
    selector: { field: valueId, operator: '<', value: 0 },
    barColor: '#D47C6A',
    barGradient: false,
    barBorderWidth: 0,
  },
]
const spec = Builder.from(seed).build()
await instance.updateSpec(spec)
```

主题切换复用已有 VChart 实例，通过 `updateSpec()` 更新；不要通过 CSS 给 Canvas 加滤镜来替代真实系列色。数值过渡、图表动画和悬停联动继续按指标卡文档处理。

需要保存、恢复或跨集成复用的主题配置，应由拥有它的 DSL 与公开 Builder 管理，不能只保存在 DOM 或浏览器本地存储中；ThemeBuilder 与主题相关 API 分别通过 [VBI 子技能](../../../api/vbi/SKILL.md)和 [VSeed 子技能](../../../api/vseed/SKILL.md)查阅。页面背景、控件样式和具体绘制仍由 UI 消费这些配置。

## 按需提供主题切换

24 份轻量模板没有内置配色选择器。仅在用户需要时，沿用宿主控件实现主题切换，并按上方 token 流程同步 DOM 与 Canvas。色点需有名称、色号、选中态和键盘焦点；初始主题按上下文选择。

切换只重绘缓存结果，复用实例，不改变日期、指标、环图分类或明细范围；下降和亏损保留语义色。通过既有刷新队列处理，避免旧查询覆盖新配色；加载反馈覆盖全部相关控件。

## 验收

按[同视口视觉对照](acceptance.md#页面布局与视觉对照)检查内容底面、图形轮廓、次要文字与标签。背景最深和最亮处都应清晰，装饰层不拦截点击或 Tooltip。确有配色切换时，再检查各主题下的数据、选中态和语义色一致。

## 统一表格主题

主页与分析明细共用[表格 token 与适配器](../../visual-query/references/table-theme.md)，色板在 CSS 中声明，图表与 VTable 消费同一主题输入，不在 Builder 输出上逐页补写表头颜色。表格保持轻量表头、弱行分隔、柔和斑马纹与右对齐数值；选中态使用主题色浅填充和 1px 细框，表头点击仅选择当前单元格。底部表格容器继续比上方卡片更透明。
