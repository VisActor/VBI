# 核心发现与指标洞察

核心发现回答“当前最值得注意的是什么”。默认一个主要判断、少量直接证据；证据已包含在结论中时不必再列一次。不要求凑齐多个北极星指标或固定数量的衍生指标。

## 结论、范围与证据

- 结论说明有数据支持的关系、变化或分化，不把所有可算指标拼成一句话。例如“销售额增长 41.5%，订单数持平，客单价同步提升”；不据此推断提价或客户升级。
- 默认一小段结论，必要时补 1–3 条证据；这是内容取舍的起点，不是固定行数或高度。删除与主要判断无关的依据，保留会改变判断的重要反例。
- 当前范围、比较基准和必要限制就近简述；标题已表达的范围不反复抄写。完整公式、数据质量限制按需展开。
- “核心 / 衍生”用于选择指标，不作为用户文案；不展示“3 项核心指标 / 2 项衍生指标”、AI 工作过程、依赖诊断或验收日志。
- 窄屏允许自然换行；先精简内容，不靠缩小文字或裁切控制高度。布局见[信息密度与模块取舍](layout.md#信息密度与模块取舍)。

没有时间或可比基期时描述有效的当前分布与差异，不编造趋势。相关性不等于因果、样本均值不等于人口加权结果、字段相等比例不等于贡献率。只保留当前判断需要的限制，避免把所有免责声明塞进结论。

## 计算口径与比较单位

基础聚合由 VBI → VQuery 执行，衍生指标消费同一筛选范围的未格式化结果。本期和前期保持地区、去重键、币种及统计粒度一致。

- **先汇总再相除**：利润率为总利润 / 总销售额，客单价为总销售额 / 全区间去重订单数；不能平均每日比率或累加每日去重数。
- 分母必须符合业务定义。零分母、缺失值显示 `—` 或简短说明，不补零或加极小常数；负利润保留。中间计算保留精度，仅展示时舍入。
- 相对变化率为 `(本期 − 前期) / abs(前期) × 100%`；前期为零时保留本期值并说明暂无可比基数。
- 比率变化默认用**百分点**：10% → 12% 为提升 2 个百分点，相对增幅才是 20%。当前值与变化分别判断有效性，不因前期无效隐藏本期值。
- 增减不自动等于改善或恶化；退款率等反向指标按业务解释。颜色不作为唯一信号。

优先选能解释主结论的衍生指标：利润率解释盈利效率、客单价解释金额与订单的关系、占比解释结构。有真实目标才计算目标差距。结论引用的值必须可由同一范围的结果核对，避免“结合某指标查看表现”这类占位句。

需要 AI 总结时，调用方先提供已计算的数值、公式、单位、比较结果、有效性和范围；Insight Builder 只管理内容，不执行模型推理。需要保存、恢复或跨集成复用的公式和依赖，应在所属 DSL 与 Builder 建模；保存 Insight 文本不等于保存可重算公式，见[派生计算与状态](../../visual-query/references/query-and-render.md)。

## Insight 资源与联动

通过 `insight.setContent(content)` 保存结论、范围与必要证据，Dashboard 引用同一个 Insight 资源。UI 用 `textContent` 与原生列表渲染，不把返回内容直接当 HTML 执行。

沿用所选模板的写入与解析协议：部分模板是“结论、范围、证据”，完整示例是“范围、结论、证据”。这些行序是页面协议，不是 VBI 领域定义；精简内容时同时调整解析，不交叉套用。

全局筛选后同步更新聚合、衍生指标和结论，旧查询不能覆盖新范围；局部悬停不覆盖全局 Insight。布局与配色切换保留结论。订阅、释放与快照见[状态与资源](../../visual-query/references/composition.md#同时保存-dashboard-和资源)。

## 验收

- 主要判断明确、证据足够且无机械复述；范围和比较口径可见，无虚构归因或制作日志。
- 核对适用的去重、分母、百分点、缺失值与负值；筛选后重新计算，悬停不改洞察，窄屏不裁切。
- 保存恢复后结论与依据完整；若承诺公式可重算，另验证公式与依赖的恢复。
