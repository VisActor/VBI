# 轻量模板接入与场景核对

本篇维护可运行模板的复用入口与核对基准；排版、配色和验收分别由对应参考维护。查询、渲染、组合与联动先按 [visual-query](../../visual-query/SKILL.md)执行；浏览器模块加载、静态数据内置和图表 / 表格接入统一见 [HTML 接入](../../visual-query/references/html-integration.md)。

## 从参考实现选择起点

先看[可视总览](../templates/index.html)：共 24 份模板，包括 20 份行业模板、3 份专题数据模板和 1 份经营概览模板。行业模板内嵌十个行业的完整 CSV，配置在 `page-config`，完整数据在 `source-data`；专题数据与经营概览模板的接入方式见下表。各模板展示不同分析重点、布局、主题与数据口径，选择最接近任务的一份，按以下顺序适配：

1. 复制完整模板 HTML，保留样式、脚本与内嵌数据。
2. 在目标环境运行，核对默认态、一次有效筛选、悬停恢复和分析返回（如有），保存对照截图；加载或交互异常先修复，再开始业务适配。
3. 替换业务数据、字段映射、统计口径、资源 ID 和文案，再按需要局部调整布局与图形。
4. 按[验收标准](acceptance.md)与运行基线对照，确认适用的呈现、联动和生命周期机制没有退化。

| 示例                                                                | 适合学习                                       | 阅读代码时关注                                                     |
| ------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------ |
| [模板 1：趋势主导](../templates/template-life-expectancy.html)      | 预期寿命年度趋势；蓝色主辅布局                 | `prepareRows()`、`conditionsFor()`、`buildView()`、`drawPlot()`    |
| [模板 2：指标先行](../templates/template-heart-failure.html)        | 心衰记录概览与年龄组比较；紫色指标行           | 同一查询范围的核心指标、事件占比与局部查看                         |
| [模板 3：分段叙事](../templates/template-meal-workout.html)         | 餐食、运动、营养及样本构成；暖橙分段布局       | 汇总比率、不同分组的图表与缓存联动                                 |
| [精简 Dashboard 模板](../templates/template-business-overview.html) | 新建轻量看板、内置数据与完整必要交互           | `draw()`、`animateMetric()`、`bindMetricHover()`、`bindCardTilt()` |
| [轻量看板](../templates/example.html)                               | 顶部洞察、汇总指标、周期比较、自定义 HTML 卡片 | `summarizePeriod()`、`rowsOf()`、`layoutDashboard()`               |

现有页面优先复用宿主组件；独立新页面以选定模板作为基座，保留成熟呈现与状态机制。布局和图形允许重组，替换成熟机制前先明确现有实现不适用的原因。完整轻量示例用于参考更丰富的配色、图标与业务数据接入。`templates/` 中的 24 份模板可以单独复制 HTML，浏览器需要联网加载 CDN 模块。完整轻量看板通过网络加载 CSV，复制为独立交付页面时，必须按[静态数据内置指南](../../visual-query/references/html-integration.md#静态独立-html-的数据内置)将 CSV 内置，并将数据初始化改为读取内联文本。

### 三种数据模板的共同机制

三份新模板在 `source-data` 中以原始列名和类型化行数组内嵌完整 CSV，空字符串保留为 `null`，不抽样、不将缺失数值补零。`prepareRows()` 映射查询字段，`conditionsFor()` 定义各查询的筛选范围；Builder 的 `observeDeep()` 合并刷新，查询后经 VSeed 构建 Spec，`drawPlot()` 复用实例调用 `updateSpec()`。`buildView()` 从查询汇总结果计算衍生指标与缓存索引；卡内查看不重新查询，也不改写区间洞察。明细默认展开，国家明细通过分页访问全部结果。

预期寿命模板使用真实年份，展示末年国家等权均值、首尾变化与有效寿命覆盖率；心衰模板只描述样本记录，死亡事件占比不等同于统一随访时点的死亡率；餐食模板以总热效应 / 总热量计算占比，以总热量 / 总食物件数计算单件热量。保留原始数据值及其缺失语义，不把样本分组比较写成因果结论。

图形、衍生公式与悬停显示属于这些独立页面的具体集成。若产品承诺跨宿主恢复整页，除 Dashboard 与资源快照外，还须明确保存或重建这些显示与计算规则，不能声称基础 DSL 已自动保存任意 HTML 计算代码。

## 复用边界与入口

模板 HTML 是可运行基座；复用其完整实现，不凭截图重新搭建或只摘取静态外壳。这里不另维护简化 HTML/CSS 或事件实现。不要把示例的指标数量、固定日期或配色切换器一起变成业务需求。

以下入口来自[经营概览模板](../templates/template-business-overview.html)，其他模板函数名可能不同，按职责对应查找：

| 可复用部分     | 源码入口                                                       | 替换业务时保留什么                                                                                |
| -------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 外壳与卡片结构 | `.shell`、`.heading`、`.card-slot`、`.hero`、`.small-body`     | 排版层级、间距、绘图区和辅助区的关系；尺寸见[布局 token](layout.md#排版与尺寸-token)。            |
| 图表构建与更新 | `buildChartSpec()`、`buildRingSpec()`、`draw()`                | 查询 seed、稳定字段 ID、统一视觉配置、实例复用及更新动画；按真实数据换图形。                      |
| 数字与局部查看 | `animateMetric()`、`bindMetricHover()`                         | 当前显示值接续、汇总恢复、事件作用域和键盘操作；遵守[指标语义](metric-card.md#指标与图形的语义)。 |
| 布局与尺寸     | `layoutDashboard()`、ResizeObserver                            | 从 Dashboard DSL 读布局，同步 DOM 顺序与图表尺寸，保留焦点。                                      |
| 加载与动效     | `data-initialized`、`entranceTiming`、`bindCardTilt()`         | 可测量的加载布局、错误反馈、入场与倾斜分层、减少动态效果及销毁清理。                              |
| 筛选与明细     | `applyFilters()`、`requestRender()`、`renderLoop()`、`details` | 查询过期保护、同步更新、不重建明细外壳、不覆盖用户折叠状态。                                      |
| 指标分析       | `bindMetricAnalysis()`                                         | 继承已确认范围、局部下钻与返回；按[分析规范](../../metric-analysis/SKILL.md)替换问题和指标。      |

图表视觉在页面内集中构建，再调用 `updateSpec()`。更换图形时保留或重新应用统一装饰，避免用手写 Spec 整体覆盖已构建结果，丢失透明背景、字体、标签和动画。最终检查传给渲染器的 Spec 与真实画面，不能只检查中间 seed，见[绘图表面要求](design.md#图表配色与页面同步)。

可保存的布局、分析条件与资源引用归 DSL / Builder；适配器做字段和宿主映射。CSS、Canvas 装饰、动画和临时 hover 归呈现层。复用页面不能替代 headless 能力，也不能把 DOM 状态作为业务状态的唯一来源。

## 模板运行核对

模板就绪后做[同视口验收](acceptance.md)。静态交付需内嵌完整业务数据；CDN 依赖不等于离线可用，按交付环境验证模块加载。模板例值仅用来确认改造前的基座正常，新业务必须换成自己的核对基准。

经营概览模板内置 60 天演示数据，共 240 条商品明细、120 个去重订单，截止 2026-09-29。同一订单有两条明细；全部地区 30 天消费者订单为 40 单，占比约 66.7%，不能按明细条数计算。

| 全部地区周期 | 销售额   | 去重订单数 | 利润    |
| ------------ | -------- | ---------- | ------- |
| 30 天        | ¥154,400 | 60         | ¥16,494 |
| 14 天        | ¥76,960  | 28         | ¥8,890  |
| 7 天         | ¥39,656  | 14         | ¥4,116  |

华东 30 天应为 ¥74,800、30 单、利润 ¥7,977。全部地区 30 天利润率 10.7%、提升 1.4 个百分点、客单价 ¥2,573；7 天利润率约 10.4%、下降 2.4 个百分点。筛选后结论不能沿用前一范围的改善判断。

[完整示例](../templates/example.html)包含布局和配色切换，仅在需要这些能力时参考。它加载的 Supermarket CSV 共 9,959 条明细、最新订单日期为 2019-12-30，原始数据下的核对值如下；数据源变化后需重新核对。

## 固定版本与场景回归

模板固定使用 VBI / VQuery / VSeed 0.6.4。该版本的柱图在生成 Spec 后设置 `spec.stackCornerRadius = 0`，通过 `barRadius` 保留单柱圆角，避免整组裁剪与更新动画不同步；升级依赖时复核圆角能力与此覆盖。日期 crosshair 格式化函数保持稳定引用，验收实际过渡帧。

完整示例的利润柱图展示所选完整区间，订单环图显示客户类型占比；图例关闭筛选，避免扇区重新归一化后与消费者中心占比不一致。检查 30 → 14 → 7 → 30 天时柱体、折线与环形扇区均正确更新。当前模板悬停联动延迟为 75ms，主趋势更新全部指标，小图仅更新自身；这些参数与图形选择属于轻量场景。

## 查询与视图复用

经营概览和完整示例的销售主图、增长迷你图共用同一 Chart Builder 与查询 seed，分别生成 VSeed 配置和 VChart 实例。悬停订阅按视图容器保存，避免迷你图覆盖主图的实例绑定。完整示例切换配色只重绘缓存结果；日期筛选才重新查询。

最新日期也由 VBI 的 `max` 度量查询。HTML 卡片与区域表只映射查询字段、格式化数字和计算明确的比率，不重新分组、求和或计数。
