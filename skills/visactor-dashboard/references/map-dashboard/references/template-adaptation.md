# 模板适配

默认复制完整模板并运行，再替换业务数据和展示槽位。保留适用的通用机制；不匹配的数据粒度、业务图表与动效可以删除或替换。已有宿主和用户指定设计优先，改变能力时说明原因并按[验收标准](acceptance.md)核对结果。

## 复用边界

- 成套继承主题 token、底图与叠色、玻璃表面、排印、响应式和入场编排。更换其中一项后检查整体层次与可读性，不凭单个 CSS 属性判断还原。
- 保留查询刷新、请求取消、原位更新、导航避让、详情返回与销毁机制；改业务回调，避免在外围再搭同职责模块。
- 替换指标、维度、图表、列表和来源说明；没有历史、层级或关系数据时移除相应趋势、下钻或飞线，也清理事件、图例与文案。
- 语义仍适用时优先保留模板图型与图例布局。改图型时说明业务收益，并一起适配绘图区、轴与图例占位；在实际卡片尺寸逐类检查标签，隐藏或截断的名称必须有可验证的完整读取路径。图表实例存在或页面无溢出不能证明可读性。
- 首屏只保留理解当前结果必需的信息和简短发现。样本均值排行同步查询、展示有效样本量；统计口径变化不能藏在字段重命名中。

## 字段与完整记录

先建立源列到业务字段的映射，再修改查询与渲染。字段标识、显示名称和 Builder 节点 ID 分别使用，不靠相似名称隐式互换。

- 在接入层将带空格、点号等源列映射为稳定字段标识，例如 `Country → country`、`PM2.5 AQI Value → pm25Aqi`、`PM2.5 AQI Category → pm25Category`。schema、Builder、筛选和渲染沿用同一业务字段；保留原列名用于溯源和导出，不改变源值与地域口径。不要把含点号的源列直接当成 SQL 限定路径，也不要只修改显示别名便认为字段已转换。
- 源值与展示兜底分开存放。例如 `city` 保留源城市值，`cityLabel` 或渲染函数才将空值显示为“城市未填写”；不要在接入时用这类文案覆盖业务字段。筛选需要的缺失分组标识也使用独立派生字段。导出原始字段时保留原空值、合法零和原类别，不能将展示兜底或筛选占位符写回 CSV。
- 业务地域字段与定位用的 ISO、GeoNames 标识分开。地域统计、排行和筛选沿用声明的业务口径；无法映射地理标识的非空地域仍计入原地域数，不能把可映射 ISO 的数量标为原始国家／地区总数。若另展示定位覆盖，单独说明其范围与分母。
- 为每条记录保留稳定 ID 和完整业务对象。查询投影只返回所选字段，不能把它默认当作完整实体：`Country` 不会自动变成 `country`，只查分指数数值也不会附带类别。地图、列表、悬停和详情共用同一 ID 与完整记录读取入口；可在点位查询中投影所需全部字段，或用查询返回的 ID 回查接入层已建立的记录索引。范围与聚合仍由 Builder 查询决定，不在详情中另算全局统计。
- 接通 UI 前，选一条具有完整事实字段的记录，核对源记录 → 接入对象 → 查询结果 → 地图／列表／详情。逐项比较 ID、地域、主值、子指标、类别、单位和定位状态；再检查真实缺失值与未定位记录。缺失字段应在正确的边界被发现，不能因漏投影而把已知值显示为“未填写”，也不能用默认零掩盖丢值。

保真断言以独立读取的原始输入为期望，允许声明过的字段改名与类型转换，不允许将空源值变成展示文案后再称为源值一致；不能在比较前把展示占位符逆向还原以掩盖字段改写。不要只把同一适配器生成的两份对象互相比较；除完整记录外，还需覆盖真实空值、合法零与未定位记录，并实际下载、解析导出文件核对这些样本。

例如点位查询只取 `id` 和空间编码时，详情可共用完整记录索引：

```js
const recordsById = new Map(records.map((record) => [record.id, record]))
const visibleRecords = pointRows.map((row) => {
  const record = recordsById.get(row.id)
  if (!record) throw new Error(`查询记录无法对应源记录：${row.id}`)
  return record
})
```

这里的 `records` 是接入后的完整业务对象，`pointRows` 是当前 Builder 范围的查询结果。不要用数组位置或城市名称代替 ID 回查，避免同名城市、重复采样记录和排序变化导致记录混淆。

## 标准模板的修改入口

[template.html](../templates/template.html)是唯一标准模板，以地震观测为业务示例。先查文件顶部模块指南；它是单文件模板，没有统一的业务配置对象，不要假定存在额外适配 API。超市示例按其 [GUIDE](../templates/supermarket/GUIDE.md) 修改。

| 职责           | 现有入口                                                                           | 适配方式                                                                                                                               |
| -------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 通用外观与启动 | `map-ui-styles`、`map-ui`、`MapUI.createAppearance`、`MapUI.loading`               | 保留完整主题与语义 token、共享浮层材质、分段入场、控件和启动机制；`MapUI.theme()`派生渲染明暗，调整业务文案与回调。                    |
| 底图           | `basemap-assets`、`map-basemaps`、`MapBasemaps.createRenderer`                     | 保留资源与渲染机制；新增资源按[地图接入](open-street-map.md)，不修改嵌入的第三方运行时。                                               |
| 源数据与字段   | `loadFeed`、`normalize`、`SOURCE_ID`、`schema`、`refresh`                          | 替换来源、字段及 Connector ID；同步调整数据集更新与释放路径。数据接入按 [server-runtime](../../server-runtime/SKILL.md#数据接入判断)。 |
| 查询与筛选     | `chart`、`summary`、`eventTable`、`rangeConditions`、`applyRange`、`updateFilters` | 调整维度、聚合、投影与筛选条件；主屏和分析沿用同一范围，保留失败回退。                                                                 |
| 地图与详情     | `initializeMap`、`renderMap`、`eventIndex`、`recordDetail`、`renderList`           | 替换实体 ID、点标与事实字段，保留导航、选中、返回与清理。                                                                              |
| 指标分析       | `quakeMetric`、`quakeAnalysisContext`、`bindMapMetricAnalysis`                     | 替换指标、条件、分组、明细与格式，保留容器、生命周期和标题入口。                                                                       |
| 渲染与释放     | `renderMetrics`、`renderDistributions`、`render`、`refresh`、`pagehide`            | 替换业务展示，保留批量查询、原位更新、请求取消和资源释放。                                                                             |

业务文案按节点更新，并核对预期命中数量；不能让短语替换先破坏长语句、随后零命中仍静默通过。用“选择器 → 期望名称”核对实际可见与可访问名称，包括启动状态及运行时创建的节点，不扫描或改写第三方库内部符号。

通用结构容器使用“分类指标”“类别构成”等职责名称，具体业务由可见标题及数据描述表达；不要给复用容器重复硬编码业务名和单位，增加适配时漏改或词语重复的机会。指标读数、操作入口与统计口径仍需准确的业务名称。

`MapQueries.create` 的维度元组为 `[field, encoding, alias]`，度量元组为 `[field, alias, aggregate]`，聚合默认 `sum`。`MapQueries.rows` 默认返回别名键；绘制 VSeed 时用 `fieldIds` 取得内部字段 ID，不能把原始字段名和内部 ID 混用。

`MapQueries.rows` 会检查返回行是否包含 Builder 所选字段，保留合法零、空结果及 `null`，缺失键或 `undefined` 则直接报出源字段名。遇到报错先补齐接入 schema 与查询投影，不吞掉错误或补默认值继续渲染。经纬度等派生字段也必须声明，或按查询返回的 ID 回查完整记录后再绘制地图。

指标主卡与深入分析共用聚合定义及缺失值口径。`countDistinct` 不计入 `null`；若业务要把缺失也作为一组，使用独立派生的分组键并声明 schema，保留原始字段供明细与导出使用，不能只在主卡手工加一。若只统计已填地域，两处都排除缺失并明确名称。

分析查询还需避免输出键冲突：`MapQueries.rows(builder, seed, 'field')` 按源字段命名，同一字段同时作为维度与聚合度量时，不能将两列都映射成 `country`，否则维度名称会丢失。helper 会对重名输出键报错，不允许静默覆盖；默认别名模式也要求输出别名唯一。沿用模板中彼此独立的分组字段与度量字段，或在业务接入层为对应职责派生不同字段；仅改显示别名不能解决 `'field'` 模式的冲突。验收时实际打开每种指标分析，比较主卡与分析总值，并核对分组名称、选择该组后的明细与返回行为。

## 业务替换检查

1. 替换 `loadFeed` 与 `normalize`，声明真实事实粒度、稳定 ID、时间、地域和可选坐标，同步调整 `schema`；缺失数值不转成零。
2. 调整 `summary`、分布查询、`eventTable` 与 `quakeAnalysisContext`，同步聚合、投影、单位和明细；没有事件时间或历史时移除相应时间筛选、近期动效与趋势。
3. 将 `rangeConditions` 及控件改为业务筛选，保持主屏、地图、列表与分析范围一致，保留筛选失败回退与分析返回行为。
4. 替换地图、列表、详情和来源文案；核对完整实体、未定位记录、合法零与真实缺失值，删除没有真实关系依据的连线。
5. 对照整体及一个有效筛选范围的查询结果，再按[行为等价](acceptance.md#行为等价)验证直接联动、分析返回、刷新与清理。
