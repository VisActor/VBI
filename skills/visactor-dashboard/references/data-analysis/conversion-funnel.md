# 有序转化分析

回答同一批实体在哪个有序阶段没有继续，以及在指定观察窗口内完成转化的比例。

## 数据契约

- 必须有稳定实体 ID、可验证阶段、阶段时间、入口条件及观察截点。
- 声明统计单位是用户、线索、订单或会话，避免混用实体数量。
- 声明是否要求严格顺序、是否允许跳步、重复进入如何处理，以及转化窗口从哪个事件开始。
- 只使用确有证据的阶段。后续阶段独有的属性不能直接作为全部入口实体的分母分组。

## 计算规则

1. 以入口实体为基表关联阶段事件，保留未观测后续事件的实体，避免内连接缩小分母。
2. 按已声明规则确定每个实体的有效阶段及时间；异常倒序保留并标记，不将负延迟改成零。
3. 窗口转化只计入规定顺序、延迟与成熟条件均满足的实体。
4. 总转化率使用合格入口分母；相邻阶段转化率使用上一步合格实体分母，分别标明口径。
5. 区分窗口内完成、窗口后完成、未观测完成、时间异常及尚待观察；未观测完成不等于永久流失。
6. 分组汇总重新合并分子分母，不平均各组转化率。

## 查询与可恢复状态

保存实体键、阶段定义与顺序、重复事件处理、窗口、截点、成熟规则、筛选和分组维度。可派生“实体 × 窗口”关系，使用复合唯一键，保留阶段时间、异常与成熟状态。

在 VBI 集成中，阶段规则由所属 DSL / Builder 表达；公开查询支持汇总和记录追溯，具体漏斗绘制由宿主完成。

## 分析与证据

按入口来源、进入批次和观察窗口比较流失位置，明细展示原实体、阶段时间、延迟及排除原因。只有日期时使用日历日差，不伪造小时级时长。比较批次时先检查观察窗口是否可比。

## 继续分析的动线

- 先定位阶段损失，再回答“转化累积到第几天”。累计曲线在所选窗口内使用同一批成熟入口实体作固定分母，每个时点累计合格完成数，不能只对已完成实体计算累计占比。
- 比较不同窗口时，仅替换窗口条件，保留来源、批次等业务范围；如果各窗口成熟总体不同，须同时披露分母变化，不能将差异全归因于等待更久。
- 从已转化阶段进入，可以查看这些实体的延迟分布；若要回答总体转化率，必须另取入口分母，并明确分析总体的变化。
- 同时检查来源与进入批次等真实交叉分组的规模、成熟分母和转化率，避免只按小样本高比例排序。

## 结果一致性与验收补充

实体 × 窗口关系需保留原实体键与窗口复合键。多个窗口合并时，按实体去重的覆盖人数与按窗口求和的观察次数应分别命名。成熟、完成和异常标志可能交叉，不能未经定义就当作互斥状态相加。

切换窗口后，同步重算阶段计数、累计曲线及明细；图元选择和完整分组菜单应得到同一条件。查询失败或取消后不提交旧窗口结果，导出记录标明窗口、截点及异常口径。

最小复算例：10 个成熟入口实体中，窗口内完成 3 个、窗口后完成 2 个，则窗口转化率为 30%，不是已观测完成实体中的 3/5。

## 解释边界与稳健性

- 总转化改善可能来自高转化来源占比上升，而不是各来源表现改善；同时核对来源内分子分母及来源构成。只有共同可比的层才适合进一步做固定权重比较，明确它是标准化结果。
- 观察成熟不等于跟踪完整。核对后续事件迟到、采样、系统迁移与未匹配阶段；没有事件与没有发生是不同证据。合理窗口变化作为敏感性分析披露，不挑最有利窗口作为唯一结论。

## 验证

核对入口实体去重、阶段顺序和成熟分母；覆盖重复事件、跳步、倒序、零延迟、窗口边界、窗口后完成、缺失时间与空范围。验证各状态可与入口总体对账，筛选及状态恢复保持同一口径。
