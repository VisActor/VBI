# 生命周期分析

回答同一观察总体的活跃变化来自首次出现、持续活跃、间隔后重返还是停止活跃，区分观测行为与真实客户生命周期。

## 数据契约

- 明确稳定成员 ID、活跃事件、时间粒度、完整期间及历史覆盖。
- 多条事件先归并到成员周期，不能将商品行、交易或点击次数直接当作活跃人数。
- 成员从首次符合规则的周期进入总体，未来首次出现的成员不得提前计作不活跃。
- 缺少注册或获客证据时使用“首次观察活跃”；一期未活跃不等于永久流失。

## 状态与计算

1. 对已进入总体的成员补齐连续完整周期，保留当期无事件状态。
2. 将成员周期分为互斥状态：首次观察活跃、相邻周期持续活跃、间隔后重返、上期活跃本期未活跃、连续未活跃。
3. 当期活跃 = 首次观察 + 持续活跃 + 重返；上期活跃 = 持续活跃 + 上期活跃本期未活跃。
4. 活跃净变化 = 首次观察 + 重返 − 上期活跃本期未活跃 = 当期活跃 − 上期活跃。
5. 毛变化为流入与流出之和，不能用净变化代替。重返率等比例须明确总体与分母。
6. 历史解释只使用截至观察周期的事件。历史覆盖的首期通常只能建立基线，不能可靠区分真实新增与历史存量。

## 查询与可恢复状态

保存成员键、活跃规则、时间粒度、历史起点、观察截点、状态定义、归属维度与筛选。派生可查询成员周期关系，保留首次观察期、前期及当期活跃标志、状态与事件证据。

在 VBI 集成中，状态规则与一致性约束属于所属 DSL / Builder，查询与恢复不依赖界面。成员属性筛选应声明固定归属规则，避免改变总体定义却沿用旧基线。

## 分析与证据

用收支关系解释净额，补充持续活跃和连续未活跃规模。可按首次观察批次、间隔长度与事件频率下钻；明细每行一个成员周期，不能把成员周期行数当作交易数。

## 继续分析的动线

- 从净变化进入，继续看上期到本期的状态迁移：先区分流入、持续与流出，再解释毛变化和净额，避免只重复净增数字。
- 从重返进入，按间隔长度与首次观察批次比较；同时给出重返人数及明确的参考分母。分析比例时保留该分母总体，不能先筛成全是重返成员再计算重返占比。
- 从活跃规模进入，结合频率与批次组成判断是持续成员还是新出现成员支持规模；只有固定成员键和连续历史时才建立成员迁移动线。
- 固定成员集合观察后续状态，与每期重新选取当期活跃成员，是不同问题；切换时说明总体规则，不混画成同一条留存曲线。

## 结果一致性与验收补充

首次归属与历史状态应先基于所需完整历史确定，再应用观察期展示范围；不能先裁掉历史而把老成员变成首次出现。时间范围、事件筛选和成员归属筛选分别声明作用阶段。

迁移明细以成员周期为单位，保留前期及当期状态和截至当期的证据；历史展开不能泄漏未来事件。切换月份后重新查询状态，不沿用上一月标签；汇总、明细和导出使用同一已确认范围。

最小复算例：首次 10、持续 60、重返 20、流出 25，则本期活跃 90、上期活跃 85、净增 5、毛变化 55；连续未活跃成员不进入这两个活跃人数。

## 解释边界与稳健性

- 检查观察总体是否只来自当前成员表，以免删除或退出成员消失而低估流出。使用历史有效归属解释当期状态；当前组织、地区或客户等级不能默认回填全部历史。
- 活跃定义、完整周期与允许间隔会改变状态迁移。对关键定义做合理范围内的敏感性比较，排查采集缺口或事件迟到造成的“未活跃”；固定定义下再解释业务变化。

## 验证

核对五类状态互斥且覆盖已进入总体，验证两期活跃与净变化恒等式。覆盖首次观察、连续活跃、隔期重返、连续未活跃、不完整周期与历史不足；检查无未来信息泄漏，筛选与状态恢复后重新对账。
