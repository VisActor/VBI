# 核心发现与指标洞察最佳实践

适用于 Dashboard 顶部“核心发现”与经营结论。**用一句有证据的结论连接核心指标与重要衍生指标，再展示范围、比较基准和逐项依据。** 核心指标描述规模，衍生指标补充结构、效率与质量，不能只罗列原始数值，也不能用未经计算的判断替代证据。版面比例与响应式由[布局最佳实践](./layout.md)负责。

参考[精简模板](../../examples/dashboard/template.html)与[完整轻量看板](../../examples/dashboard/lightweight-dashboard.html)的 `deriveMetrics()`、`pointChange()`、`summarizeKeyFinding()`；完整示例的 `summarizePeriod()` 组织证据，模板在 `renderLoop()` 中写入同一 Insight 资源。

## 结论、范围与证据

“核心发现”模块按以下阅读顺序组织，标题不添加“AI 洞察”“指标波动 · 摘要演示”等技术或演示标识：

1. **一句重要结论**：先说本期最值得关注的关系或分化，例如“销售额增长，订单数基本持平；客单价提升，利润率提升。”结论应能从后面的数字直接核对，不归因于数据未提供的营销、成本或客户行为。
2. **范围与比较口径**：注明核心与衍生指标数量、起止日期、地区等生效条件和比较周期。模板使用“3 项核心指标 · 2 项衍生指标 · … · 对比前 30 天”。
3. **核心指标依据**：销售额、去重订单数、利润等，每项一句，展示本期值、变化方向与幅度；覆盖本次已声明的核心指标清单。
4. **重要衍生指标依据**：紧接核心指标列出利润率、平均客单价等已计算的结果及变化。优先选择能够解释主结论、揭示风险或补全经营表现的指标，不堆砌所有可计算公式。

以模板“全部地区、30 天”的内置数据为例：

- 销售额：¥154,400，↑ 增长 41.5%。
- 订单数：60 单，持平 0.0%。
- 利润：¥16,494，↑ 增长 63.5%。
- 利润率：10.7%，↑ 提升 1.4 个百分点。
- 平均客单价：¥2,573，↑ 增长 41.5%。

前三项是核心指标，后两项是衍生指标。销售增长率属于销售额的变化描述，不另计一个核心指标；同一客单价在主卡和洞察中出现也只计一次。衍生指标的当前值与变化率同样不重复计数。

一个列表可以同时承载核心与衍生证据，通过顺序和范围说明表达区别，无需再增加一排等权 KPI 卡。内容增加时允许洞察卡自然增高，下方模块顺延；窄屏完整换行，不能固定高度裁切、缩小字号或让文字覆盖图表。

## 选择有意义的衍生指标

| 分析问题                           | 衍生指标与公式                                         | 能补充的判断                                                             |
| ---------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------ |
| 销售增长是否伴随盈利改善？         | 利润率 = 汇总利润 ÷ 汇总销售额                         | 销售与利润率同向提升，或规模扩大但盈利效率回落。                         |
| 销售变化伴随订单量还是客单价变化？ | 平均客单价 = 汇总销售额 ÷ 去重订单数                   | 订单减少但销售增长时，客单价提升可由数据验证；不据此推断提价或客户升级。 |
| 流量是否形成有效结果？             | 转化率 = 符合口径的转化数 ÷ 同口径机会数               | 规模与转化效率是否分化；需先确认去重对象、漏斗阶段和时间窗口。           |
| 总量掩盖了什么结构？               | 某类占比 = 该类指标 ÷ 全部同口径指标                   | 收入、客户或订单结构变化；分类需互斥或明确重叠口径。                     |
| 表现离目标还有多远？               | 完成率 = 实际值 ÷ 已确认目标值；缺口 = 目标值 − 实际值 | 进度与剩余任务；没有真实目标时不编造目标或阈值。                         |

选择取决于业务问题和可用字段。模板仅新增利润率与平均客单价两项，其他公式是按需选用的示例，不能在缺少分子、分母、目标或业务定义时补造数据。占比或高客单价也不天然代表更好，需要结合业务含义解释。

## 计算口径与比较单位

基础聚合仍由 VBI → VQuery 执行，衍生指标消费同一筛选范围的未格式化汇总结果。本期和前期分别计算，地区、去重键、币种与统计粒度保持一致。**先汇总再相除**：利润率用 `sum(profit) / sum(sales)`，客单价用汇总销售额除以全区间去重订单数；不能平均每日比率，也不能累加每日去重订单数代替全区间去重数。

模板中正销售额、正订单数才构成有效分母；利润可以为负，负利润率保留。实际业务存在净销售额为负等情况时先确认解释方式，不直接沿用正分母假设。零分母、缺失值显示 `—` 或简短说明，不能把缺失值当零，也不能用极小常数绕过除零。中间计算保留精度，仅展示时舍入。

```javascript
function deriveMetrics(total) {
  const ratio = (value, base) =>
    Number.isFinite(value) && Number.isFinite(base) && base > 0 ? value / base : undefined
  const margin = ratio(total.profit, total.sales)
  return {
    margin: margin === undefined ? undefined : margin * 100,
    average: ratio(total.sales, total.order_id),
  }
}
const current = deriveMetrics(total)
const previous = deriveMetrics(prior)
// 利润率已经是百分数单位，差值直接表示百分点；客单价比较相对变化率。
const marginPoints =
  Number.isFinite(current.margin) && Number.isFinite(previous.margin) ? current.margin - previous.margin : undefined
```

- 金额、数量或客单价的相对变化率：`(本期 − 前期) / abs(前期) × 100%`。前期为零不显示增速，保留本期值并说明暂无可比基数。
- 比率的水平变化默认用**百分点**。利润率从 10% 到 12% 是提升 2 个百分点；如确需相对增幅则是 20%，必须明确标注，不能混写为提升 2%。前期利润率为 0% 仍可比较百分点，只要两期分母都有效。
- 当前值与变化分别判断有效性：本期有值但前期无有效分母时，仍展示本期衍生指标，变化说明不可比；某项缺失不掩盖其他可比较指标。
- 箭头表示实际增减，文字保留“增长 / 下跌”“提升 / 下降”及单位，颜色不作为唯一信号。本销售示例增长用绿、下跌用红，持平与不可比用中性色；退款率等反向指标按业务解释好坏，不能把增长一律写成改善。

本页公式是示例中的呈现层计算，没有增加 VBI 公式 DSL。若指标公式、依赖及口径需要作为 VBI 能力保存、恢复或跨集成复用，应在所属 DSL 和 Builder 中建模；保存 Insight 文本并不自动保存可重算的公式。能力边界见[派生计算与状态](../usage/tips.md)。

## 从数值形成更全面的结论

先比较规模，再结合相关衍生指标检查效率与质量是否一致。例如销售额上升、订单数下降而客单价上升，可以描述三者的关系；若利润率同时下降，结论必须保留这一分化，不能只报告销售增长。利润绝对值增长不等于利润率提高，增长速度相同也不意味着经营原因相同。

结论引用的衍生指标必须出现在证据中，且能从同一范围的核心聚合结果复算。避免“结合利润率与客单价查看表现”这类尚未给出计算结论的占位句。缺少可比数据时明确限制，继续展示有效本期值与其他指标；不生成推测的原因、建议或业务阈值。

接入 AI 时，调用方先计算并提供核心清单、衍生清单、公式与单位、本期值、前期值、比较结果、有效性和筛选范围，再要求模型总结关系。Insight Builder 只管理内容，不执行模型推理，也不应让模型猜测或自行补齐指标。两个 HTML 示例都用真实聚合结果生成确定性结论，未调用模型服务。

## Insight 资源与联动

通过 `insight.setContent(content)` 保存结论、范围与全部证据；Dashboard 通过资源 ID 引用同一个 Insight，UI 安全地写入 `textContent` 与原生列表，不把模型返回内容直接当任意 HTML 执行。模板采用以下顺序：

```javascript
insight.setContent([conclusion, scope, ...evidence].join('\n'))
// renderInsight() 读取结论、范围与证据，渲染为 h2 / p / ul / li。
```

这只是模板的文本协议，VBI 未定义这些行的业务语义。完整轻量示例仍以范围为首行、结论为第二行、后续 `- ` Markdown 列表保存证据，渲染时将结论放到范围之前；复制时保留各自写入与解析顺序，不交叉拼接。

全局筛选后，核心聚合、衍生计算、结论、范围和证据同时更新；旧查询结果不能覆盖新范围。局部图表悬停只改变对应数字，不覆盖区间 Insight。布局与配色切换复用资源与结论，增长方向等语义颜色不随主题改变。订阅与释放、保存 Dashboard 及资源快照见[状态与资源](../usage/tips.md#同时保存-dashboard-和资源)。

## 验收

- 一句结论在前，核心与衍生指标数量、范围与比较基准清楚；各项证据可复算，结论覆盖关键改善或分化，不编造原因。
- 核对总量除以总量、全区间去重、百分点与相对百分比；覆盖零分母、零基期、缺失值和负利润，本期有效但前期不可比时仍能读到本期值。
- 模板全部地区 30 天应显示利润率 10.7%、提升 1.4 个百分点、客单价 ¥2,573、增长 41.5%；7 天利润率约 10.4%、下降 2.4 个百分点，结论不能沿用“利润率提升”。
- 切换地区与周期后重新计算，局部悬停不改洞察；桌面与窄屏下五项证据完整，无裁切、重叠或不必要的独立卡片。
- 保存与恢复 Insight 文本后结论与依据完整；若承诺公式可重算，另验证公式定义与依赖的恢复，不能仅检查文本保存。
