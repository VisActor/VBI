# VSeed

:::info 一文でまとめると
上位では業務の柔軟な要件を受け止め、下位ではデータ入力形式を制約し、データを統一的に編成して複雑さを単純化します。
:::

## VSeed とは何か?

`VSeed` はデータ分析向けの可視化ツールです。異なるチャートタイプ間で高い一貫性を持つデータ変換能力を提供することに集中し、軽量なデータ分析ニーズを満たすための一部のすぐ使える機能も備えています。

## VSeed の強みは何か

> まず非常に使いやすく、次に確かに柔軟です。さらに VSeed には多くのラッピングがあるため、VSeed がどのようにデータリシェイプを行うかを理解すると、より適切に活用できます。

1. 最も直感的なチャート切り替え方法 [Demo](/vseed/guide/intro/chartTypeSwitch)
2. 最も使いやすいピボットチャート [Demo](/vseed/guide/intro/pivotAndCombine)
3. 強力なデータリシェイプ能力。追加のデータ処理なしで、任意の数のディメンションやメジャー、任意のチャートタイプを描画できます [Demo](/vseed/guide/intro/dataReshape)
4. `VSeed` は完全にシリアライズ可能なため、`VSeed DSL` のクロスプラットフォーム転送をサポートします [Demo](/vseed/guide/intro/crossPlatformRender)
5. すぐに使える機能: 数値フォーマット、国際化、ライト/ダークテーマ、よく使うスタイルなど [Demo](/vseed/guide/intro/internationalization)
6. 優れたデータ処理性能。`Node` 側でデータを処理し、`Web` 側で可視化できます [Demo](/vseed/guide/intro/separateBuild)

## VSeed の弱みは何か

1. `VSeed` は単一チャートのすべての細部を磨き込む責務を持ちません。そのような要件は `VChart`、`VTable` が提供します。`VSeed` は `spec` を柔軟に変更する能力のみを提供し、ユーザーは自身の要件に応じてチャートの各詳細を柔軟に変更できます。
2. `tidyData` 仕様に準拠したデータセットだけが `VSeed` で可視化できます。標準に合わないデータセットは `VSeed` では受け付けません。
3. `VisActor` エコシステムを基盤としているため、利用者は `VChart` と `VTable` の基本概念を理解する必要があります。

## VSeed の原則は何か？

1. `VSeed` はシリアライズをサポートしなければなりません。
2. `VSeed` は過度なスタイル設定能力を提供する必要はなく、チャートとデータの関係を処理することに集中すべきです。
3. `VSeed` は分析領域でよく使われる汎用機能、たとえば数値フォーマット、国際化、テーマ、よく使うスタイルや機能をラップし、すぐに使える状態にすべきです。
4. より柔軟なカスタマイズ要件はユーザーが二次カスタマイズで満たすべきです。そのため VSeed は外部に対して、VChart / VTable の spec を構築するための Spec Builder のみを提供します。
   - ユーザーは VChart Instance と VTable Instance を柔軟に制御できます。
   - ユーザーは自身の要件に応じて、VChart / VTable の spec を柔軟に変更できます。


## なぜ VSeed を設計するのか？

1. `VChart` は `VTable` へ永遠にシームレスには切り替えられず、その逆も同じです。このような要件に対して、上位の抽象ラッパーは必然的に必要になります。
2. `VChart`、`VTable` を使うユーザーは、自分でデータを処理しなければなりません。この作業は無意識のうちに何百回、何千回も繰り返されます。`VSeed` は一般的なシーンでのデータ処理の複雑さを下げ、重複作業を減らしたいと考えています。
3. `VChart` と `VTable` の利用ハードルを一定程度下げられます。たとえば `VTable` で `PivotChart` をレンダリングできます。
4. `VSeed` は最終的に `HeadlessBI` のサブモジュールへ発展し、汎用的なデータ分析ツールの構築に使われる可能性があります。
