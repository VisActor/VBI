# DSL 設計

:::info 意義

VSeed は宣言型 DSL です。

- DSL 設計はドメイン課題を表現する技術であり、複雑な問題を効果的に単純化できます。
- DSL は、慣れた人が母語を書くように自然にコードを書けるようにします。VSeed に慣れると、チャートのレンダリングは自然言語を書くように簡単になります。
- `VChart`、`VTable` も同様です。


:::

:::tip

`宣言型 DSL` は「何であるか」（What）に注目します。期待する結果や最終状態がどうあるべきかを記述し、コンピューター内部でその状態に到達する具体的な手順には関与しません。


`命令型 DSL` は「どのように行うか」（How）に注目します。明確で段階的に実行される一連の命令を提供し、コンピューターに目標状態へ到達する手順を伝えます。
:::

## VSeed のトレードオフ

1. ドメインへの集中（Focus）

一定の汎用性を犠牲にし、特定ドメインの課題解決に集中します。そのため VSeed の中核目標は、1 つのチャートタイプのあらゆる要件を深く満たすことではなく、チャートタイプへ到達する前のデータ変換に集中することです。テーマ、インタラクション、アニメーションなどのその他の機能は別の責務です。

2. 抽象レベル（Abstraction Level）

`VSeed` は高い抽象レベルを提供し、ユーザーが下位の実装詳細ではなく課題解決に集中できるようにします。これにより開発効率が向上します。たとえばチャートタイプの切り替えは、切り替えの詳細を意識せずに 1 つのパラメータを変更するだけで行えます。

3. 制約は強み（Constraint is Advantage）

`VSeed` は制約を重視し、`VSeed DSL` を受け取り、`VTable` または `VChart` の `spec` を出力します。これにより、ユーザーは単一チャートの機能をより柔軟に制御できます。`VSeed` はブラックボックスではありません。

したがって VSeed は単純に `Spec Builder` と見なせます。`VTable` や `VChart` の元の機能を壊さず、どの `VChart` / `VTable` ユーザーでも既存のプラットフォームへすばやく `VSeed` を導入できます。
