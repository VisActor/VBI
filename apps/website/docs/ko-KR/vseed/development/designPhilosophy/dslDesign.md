# DSL 설계

:::info 의미

VSeed는 선언형 DSL입니다

- DSL 설계는 도메인 문제의 표현 예술로, 복잡한 문제를 효과적으로 단순화할 수 있습니다.
- DSL은 익숙한 사람이 모국어를 쓰듯 자연스럽게 코딩할 수 있게 합니다. VSeed에 익숙해지면 차트를 렌더링하는 것이 자연어를 쓰는 것처럼 간단해집니다.
- `VChart`, `VTable`도 이와 같습니다


:::

:::tip

`선언형 DSL`은 '무엇(What)'에 중점을 둡니다. 기대하는 결과나 최종 상태가 어떻게 되어야 하는지를 설명하며, 컴퓨터 내부에서 해당 상태에 도달하는 구체적인 단계에는 관심을 두지 않습니다.


`명령형 DSL`은 '방법(How)'에 중점을 둡니다. 컴퓨터가 목표 상태에 단계별로 도달하는 방법을 알려주는 명확하고 순차적으로 실행되는 일련의 명령을 제공합니다.
:::

## VSeed의 장단점

1. 도메인 집중성 (Focus)

일정 수준의 범용성을 희생하고 특정 도메인의 문제 해결에 집중합니다. 따라서 VSeed의 핵심 목표는 하나의 차트 유형의 모든 요구 사항을 깊이 있게 충족하는 것이 아니라 차트 유형 이전의 데이터 변환에 집중하는 것입니다. 나머지 기능(테마, 상호작용, 애니메이션 등)은 별도로 처리됩니다.

2. 추상화 수준 (Abstraction Level)

`VSeed`는 높은 추상화 수준을 제공하여 사용자가 문제 해결에 집중할 수 있게 하고 하위 구현 세부 사항에 신경 쓰지 않아도 됩니다. 이를 통해 개발 효율성이 향상됩니다. 예를 들어 차트 유형을 전환할 때 하나의 매개변수만 변경하면 되며 전환 방법의 세부 사항을 알 필요가 없습니다.

3. 제약이 곧 장점 (Constraint is Advantage)

`VSeed`는 제약을 강조합니다. `VSeed DSL`을 입력받아 `VTable` 또는 `VChart`의 `spec`을 출력하므로, 사용자가 개별 차트의 기능을 더 유연하게 제어할 수 있습니다. `VSeed`는 블랙박스가 아닙니다.

따라서 VSeed는 간단히 `Spec Builder`로 간주할 수 있으며, `VTable` 또는 `VChart`의 원래 기능을 손상시키지 않으므로 모든 `VChart`, `VTable` 사용자가 기존 플랫폼 내에서 VSeed를 빠르게 도입할 수 있습니다.
