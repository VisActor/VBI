# Test process

VSeed adopts a strict test-driven development process. **All test commands must be executed in the project root directory. **

## Test classification

### 1. Unit Tests
- **Goal**: Test independent tool functions and Pipeline node logic.
- **Location**: `packages/vseed/tests/unit`
- **Run**:
  ```bash
  pnpm --filter=@visactor/vseed run test:unit
  ```

### 2. Integration Tests
- **Goal**: Test the complete chart generation process (VSeed Spec -> VChart Spec).
- **Mechanism**: Data driven. Automatically generate test cases and compare snapshots by reading the JSON file under `packages/vseed/tests/integrations`.
- **Run**:
  ```bash
  pnpm --filter=@visactor/vseed run test:integration
  ```

## Core Workflow (Workflow)

### Step 1: Run the test
During development, run relevant tests frequently to verify logic.
```bash
# 运行所有测试
pnpm --filter=@visactor/vseed run test
```

### Step 2: Process snapshot changes
If the code is modified causing the output Spec to change (for example, a bug is fixed or a Feature is added):
1. Check the Diff output on the console to confirm whether the changes are as expected.
2. If it is as expected, run the update command:
   ```bash
   pnpm --filter=@visactor/vseed run test:update
   ```

### Step 3: Coverage Check
Before committing code, it is recommended to check test coverage.
```bash
pnpm --filter=@visactor/vseed run test:coverage
```

## Notes
- **Automatically generated**: The `.test.ts` file of the integration test is generated by the `g` script, **Please do not modify it manually**.
- **New use case**: To add a new integration test, just add a new JSON configuration file in the corresponding category directory under `packages/vseed/tests/integrations`, and then run `pnpm run g`.
